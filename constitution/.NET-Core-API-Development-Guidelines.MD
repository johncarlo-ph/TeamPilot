# .NET Core API Development Guidelines

## General

- **Human-readable code:** Prioritize clarity over cleverness.
- **Proper documentation:** Use JSDoc/TSDoc-style comments for classes, methods, and complex logic where applicable. In C#, use XML documentation comments when they are supported by the project tooling.
- **Consistent naming:** Follow Angular style guide conventions: use `camelCase` for variables and `PascalCase` for classes.
- **StyleCop:** Enforce coding standards and linting rules to maintain consistency and readability across the project.
- **Descriptive names:** Avoid unnecessary abbreviations; prefer descriptive names for components, services, and models.

## Clean Architecture

- **Layer separation:** Organize the solution into Domain, Application, Infrastructure, and Presentation layers.
- **Dependency rule:** Inner layers must not depend on outer layers.
- **Entities:** Keep core business models and rules in the Domain layer.
- **Use cases:** Let the Application layer orchestrate business logic.
- **Infrastructure:** Use this layer for persistence, external services, and framework-specific concerns.
- **Presentation:** Keep API controllers and request/response models in the Presentation layer.

## SOLID Principles

- **Single Responsibility:** Each class or module should have one reason to change.
- **Open/Closed:** Classes should be open for extension and closed for modification.
- **Liskov Substitution:** Derived types must be substitutable for their base types.
- **Interface Segregation:** Prefer small, specific interfaces over “fat” interfaces.
- **Dependency Inversion:** Depend on abstractions rather than concrete implementations.

## EF Core Best Practices

- **DbContext lifetime:** Register `DbContext` with a scoped lifetime per request; never use singleton `DbContext` instances.
- **Migrations:** Use `Add-Migration` and `Update-Database` for schema evolution.
- **Business logic:** Keep entities lean and place business rules in the Domain layer rather than in persistence models.
- **Tracking:** Use `AsNoTracking()` for read-only queries.
- **N+1 queries:** Avoid N+1 queries by using `Include()` or projections with `Select()` where appropriate.
- **Transactions:** Use `IDbContextTransaction` for atomic operations that span multiple persistence actions.
- **Constraints:** Define database constraints, including unique and foreign-key constraints, alongside EF validation.
- **Indexes:** Create indexes on frequently queried columns (e.g., foreign keys, search fields, or filter criteria) to improve performance.

## Object-Oriented Programming

- **Encapsulation:** Hide internal state and expose behavior through methods.
- **Inheritance:** Use inheritance judiciously; prefer composition when it provides a clearer design.
- **Polymorphism:** Enable flexible behavior through interfaces and abstract classes.
- **Abstraction:** Define contracts through interfaces for services and repositories.
- **Domain models:** Prefer rich domain models with behavior over anemic data containers.

## Unit Testing

- **Test pyramid:** Maintain a majority of unit tests, fewer integration tests, and a minimal number of end-to-end tests.
- **Isolation:** Mock repositories and external service dependencies.
- **Arrange-Act-Assert:** Structure tests using clear Arrange, Act, and Assert sections.
- **Naming:** Use descriptive names following `MethodName_StateUnderTest_ExpectedBehavior`.
- **Coverage:** Focus coverage on business logic rather than trivial getters and setters.
- **Tools:** Use xUnit or NUnit with Moq or FakeItEasy for mocking.

## Additional Guidelines

- **Security:** Use HTTPS, validate inputs, sanitize outputs, apply OWASP guidelines.
- **Logging:** Use structured logging.
- **Error** handling: Centralize exception handling with middleware; return consistent error responses.
- **Validation:** Use DataAnnotations or FluentValidation; return meaningful error messages.
- **Performance:** Cache frequently accessed data; use async/await properly.
- **CI/CD:** Automate builds, tests, and deployments; enforce code quality gates.
- **Documentation:** Generate API docs with Swagger; keep them updated.
